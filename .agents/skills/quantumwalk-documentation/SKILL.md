# Documentation

- Document verified behavior and current implementation, not aspirations as if already shipped.
- Keep the primary README and AGENTS instructions concise; put detailed references in focused docs.
- Include setup prerequisites, exact commands, expected results, configuration names, and troubleshooting.
- Never include real secrets, private data, or production identifiers.
- Update docs when APIs, environment variables, migrations, or user-facing behavior change.
- Prefer concise tables and examples over duplicated prose.
- Label assumptions and known limitations clearly.
